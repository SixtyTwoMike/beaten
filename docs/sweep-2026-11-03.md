# Security and performance sweep — 2026-11-03

Commit after `ffc8c28`. Local tests: API smoke and browser e2e all pass.

## Security

| # | Finding | Severity | Status |
|---|---|---|---|
| 1 | Admin pages (`/admin`, `/admin/achievements`) were gated only by `admin/layout.tsx`. Next.js warns a layout doesn't stop its pages rendering (`node_modules/next/dist/docs/01-app/02-guides/authentication.md`, "Layouts and auth checks"). Not reproduced as a bypass, but the pages had no check of their own. | Medium | Fixed: each page calls `requireAdminPage()` |
| 2 | Responses carried `X-Powered-By: Next.js` | Low | Fixed: `poweredByHeader: false` |
| 3 | `satori` < 0.33.5 escapes SVG improperly (GHSA-wx4j-mvgx-mqwp). Our client previews are only shown through `<img>` (no script). Server cards use the satori inside Next's `@vercel/og` (0.29.0 even in Next 16.4.4), rendered by resvg as WASM with no file or network access, so the output is just a PNG. 0.33.5 breaks the browser build (harfbuzzjs needs `fs`). | Low here | Open: revisit when Next updates `@vercel/og` |
| 4 | `deepmerge-ts` advisory, reached via the Prisma CLI config (build and migrate time only, no untrusted input) | Low | Open: comes with the next Prisma major |
| 5 | Content-Security-Policy is only `frame-ancestors 'none'` | Low | Open: a full CSP needs nonces for Next's inline scripts |

Checked and fine:
- **Access checks:** every `/api/v1` route checks the token. Public routes are only sign-in, register and the public card images. Every server action checks the user, either directly or through a shared helper. Every signed-in page checks the user itself.
- **Redirects:** `callbackUrl` only accepts paths on this site.
- **Steam sign-in:** the callback checks the nonce and confirms the response with Steam (`check_authentication`). Mock mode only comes from server settings, and all three `*_MOCK` flags are `0` on the box.
- **XSS:** no `dangerouslySetInnerHTML` anywhere.
- **Headers and nginx:** HSTS, `X-Frame-Options`, `nosniff` and `Referrer-Policy` are present. nginx rate-limits sign-in, POSTs, cards and the API.
- **Earlier QA report:** #3, #4, #5, #6, #7 and #8 have been fixed since it was written.

## Performance

These numbers come from a production build with a heavy test account: 2,000 diary entries, 400 copies, 200 Pull List games, 10 shelves and 40 friends.

| Page / endpoint | Before | After |
|---|---|---|
| `/log` (diary) | 17.5 MB, 541 ms | 1.2 MB, 97 ms |
| `/` (home) | 675 KB | 137 KB |
| `/<username>` (public profile) | 899 KB, 81 ms | 496 KB, 66 ms |
| `GET /api/v1/logs` | 1.7 MB | 1.0 MB |
| `GET /api/v1/users/:username` | 250 KB | 37 KB |
| `GET /api/v1/shelves` | 239 KB | 65 KB |

What changed:
- **Diary:** shows 100 entries, then "Show more". Shelved and "finished a while ago" show 30, then "Show all". It no longer loads game summaries.
- **"Currently playing":** limited to 16 on home (with "All N →" linking to the diary filter) and 24 on profiles (web and API), with an "and N more" line.
- **App list endpoints:** logs, shelves, feed, profile and chronicle leave out game summaries. The app shows them from `GET /games/:id`.
- **New index:** `SteamGame(igdbId)`. Game pages looked up Steam owners by scanning the whole table.
- **Platform list:** held in memory for 10 minutes. It used to cost three queries on every page that needed it.

Query counts don't grow with data: the diary runs 14 queries whether it has 20 entries or 2,000, so there's no N+1. Signed-in pages run 7–25 small queries, mostly in parallel, in 10–60 ms.

Not changed, worth watching:
- **Collection page:** renders every copy on the client, about 480 KB for 400 copies. That's fine at today's sizes, but it needs paging well before the 5,000 cap.
- **SQLite journal mode:** the database uses the default rollback journal. Switching to WAL would let reads carry on while the 15-minute notification job writes. The database is small (0.8 MB), so this is low priority.
- **Server memory:** the box has 909 MB of RAM, Umami and Docker run alongside the app, and about 340 MB of swap is in use. Keep an eye on it as traffic grows.
